RECETON - PRUEBAS ALTERNATIVAS CON CMD Y CURL
Versión: OAuth 2.0 Authorization Code + PKCE y JWT (access token de 20 minutos)
Servidor por defecto: http://api.receton.test:8080

IMPORTANTE
- Ejecuta los comandos desde CMD (Símbolo del sistema), no desde la consola SQL.
- El equipo cliente debe tener conectividad de red con la laptop servidor. Si cambia la IP del servidor, actualiza el archivo hosts en ambas laptops con los scripts del ZIP 04; no cambies estos comandos.
- Las rutas protegidas /api/** requieren Authorization: Bearer <JWT vigente>.
- La autenticación es OAuth 2.0 Authorization Code + PKCE; las rutas protegidas reciben un access token JWT firmado.
- Usa una cuenta activa con rol Administrador para los CRUD de escritura y el CRUD de usuarios.

A) COMPROBAR CONECTIVIDAD (no requiere autenticación)
  curl.exe -i http://api.receton.test:8080/saludo
  curl.exe -i http://api.receton.test:8080/adios

Respuesta esperada en /saludo: HTTP 200 y texto "Holaaaaa que hace".

B) OBTENER JWT PARA LAS PRUEBAS
El flujo configurado es OAuth 2.0 Authorization Code + PKCE. No uses el endpoint antiguo /api/autenticacion/iniciar-sesion: la colección de esta versión usa el servidor de autorización /oauth2/authorize y /oauth2/token.

Forma recomendada (Postman): en la colección, pestaña Authorization, pulsa Get New Access Token con Authorization Code (With PKCE), callback https://oauth.pstmn.io/v1/callback, client_id receton-angular, scopes api.read api.write y SHA-256. Inicia sesión en el formulario seguro y pulsa Use Token.

Alternativa para ejecutar los comandos CMD después de obtener el token: copia el access_token en la sesión local de CMD, sin compartirlo ni incluirlo en capturas:
  set "RECETON_TOKEN=PEGAR_ACCESS_TOKEN_JWT"

El JWT vence a los 20 minutos según la configuración actual. Cuando expire, obtén uno nuevo mediante OAuth 2.0. No coloques credenciales ni tokens en documentos compartidos.

C) CONSULTA PROTEGIDA
  curl.exe -i "http://api.receton.test:8080/api/categorias" -H "Authorization: Bearer %RECETON_TOKEN%"

D) LOS 20 ENDPOINTS DEL MANUAL
La colección de Postman ya contiene cuerpos y variables automatizadas. Para CMD, ejecuta cada comando individualmente y reemplaza los IDs de ejemplo por los que devuelve el POST anterior.

1. CATEGORÍAS
GET
  curl.exe -i "http://api.receton.test:8080/api/categorias" -H "Authorization: Bearer %RECETON_TOKEN%"
POST

E) CÓMO INTERPRETAR ERRORES
- 200: lectura o actualización correcta; algunas operaciones de imágenes devuelven la lista resultante.
- 201: registro creado.
- 204: eliminación correcta, sin cuerpo de respuesta.
- 400: datos de entrada inválidos o faltantes.
- 401: JWT ausente, inválido o expirado, o sesión de autorización incompleta.
- 403: el usuario autenticado no tiene rol Administrador para esa operación.
- 404: ID o recurso no encontrado.
- 409: conflicto de datos; por ejemplo, un producto asociado a carrito/pedido o nombre duplicado.
- curl error 7 / conexión rechazada: backend apagado, IP/puerto incorrectos o firewall/red bloqueando.

F) SI HAY QUE ARRANCAR EL BACKEND DE NUEVO
Abre CMD y entra al directorio backend ANTES de ejecutar Gradle. Cambia la ruta si el proyecto está guardado en otra ubicación:
  cd /d "C:\Users\olaf_\OneDrive\Escritorio\proyecto_noe\backend"
  gradlew.bat bootRun

Si escribes gradlew.bat desde C:\Users\olaf_ y no estás en la carpeta backend, Windows dirá que no reconoce el comando. Si ya está activo y netstat muestra LISTENING en 0.0.0.0:8080, no hace falta iniciar una segunda instancia.
